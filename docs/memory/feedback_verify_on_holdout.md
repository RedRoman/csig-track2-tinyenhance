在 CSIG 项目里同一类错误犯了四次，每次都是**拿一个窄的或有偏的观测面，去推断全集的行为**：

1. 只看 case1/case2 就宣布「视觉验证通过」，漏掉重度退化样本上的幻觉
2. 自造的 tile 接缝检测在平坦区统计量失真，报出 13 张假阳性，据此连改三版（越改越差）
3. 用随机噪声测 jit 数值差，得出 2.5-3.9% 的虚高（噪声过 VAE 后集中于均值，放大分母误差）
4. 用 GT-based HF 诊断判定伪影「回到 run8 水平」——但 GT 只有验证集 3 张，
   而那三张正是训练验证和选 best checkpoint 用的图，模型已被专门调优过

**Why**：这类错误代价很高，因为结论听起来是「已验证」，会被当作事实往下传，
用户据此做决策。第 4 次差点让用户在不知情的情况下提交一个明显有伪影的版本。

**How to apply**：
- 下「通过 / 没问题」这类结论前，先问观测面覆盖了什么、有没有和调优过程重叠
- 优先在**真正的目标数据**（这里是 100 张测试图）上验证，哪怕没有 GT
- 改进措施让指标变差时，立刻怀疑指标本身，而不是继续改
- 长日志用 `tail` 看会截掉峰值——曾因此把「峰在 450 步、之后变差」误读成「训练越久越好」
- 自造指标要先证伪；已经造错过三次
